# STM32F103 vendor notes

## GPIO overview
The STM32F103C8 (Blue Pill) exposes ports PA0..PA15, PB0..PB15 and PC13..PC15. Each port is configured through GPIOx_CRL (pins 0-7) and GPIOx_CRH (pins 8-15), four bits per pin: MODE[1:0] then CNF[1:0]. Common nibbles: 0x4 input floating, 0x8 input with pull-up/down (select with ODR bit), 0x3 general push-pull output 50 MHz, 0xB alternate-function push-pull 50 MHz (USART TX, SPI SCK/MOSI, timer PWM), 0xF alternate-function open-drain 50 MHz (I2C SDA/SCL). Port clocks must be enabled in RCC_APB2ENR (IOPAEN, IOPBEN, IOPCEN) and AFIOEN when remapping. PC13 drives the Blue Pill LED (active low). PA13/PA14 are SWD; PA15, PB3 and PB4 are JTAG pins freed by AFIO_MAPR.SWJ_CFG=0b010.

## I2C pin mux
I2C1: SCL PB6, SDA PB7; remapped (AFIO_MAPR.I2C1_REMAP=1) SCL PB8, SDA PB9. I2C2: SCL PB10, SDA PB11. Both pins are configured as alternate-function open-drain (CNF/MODE nibble 0xF). I2C1 and I2C2 sit on APB1; enable RCC_APB1ENR.I2C1EN / I2C2EN.

## I2C timing
I2C_CR2.FREQ must equal the APB1 clock in MHz (36 at a 72 MHz SYSCLK). Standard mode 100 kHz: CCR = 36 MHz / (2 * 100 kHz) = 180, TRISE = 37. Fast mode 400 kHz with DUTY=0: set CCR.F_S=1, CCR = 36 MHz / (3 * 400 kHz) = 30, TRISE = 11. Configure while I2C_CR1.PE=0, then set PE. A transfer is START (CR1.START), wait SR1.SB, write address to DR, wait SR1.ADDR, read SR1 then SR2 to clear ADDR.

## SPI pin mux
SPI1: NSS PA4, SCK PA5, MISO PA6, MOSI PA7; remapped NSS PA15, SCK PB3, MISO PB4, MOSI PB5. SPI2: NSS PB12, SCK PB13, MISO PB14, MOSI PB15. SPI1 is on APB2 (72 MHz), SPI2 on APB1 (36 MHz); SPI_CR1.BR divides that clock by 2..256. For software NSS set SSM=1 and SSI=1 in master mode.

## USART pin mux and baud
USART1: TX PA9, RX PA10 (remap TX PB6, RX PB7), on APB2. USART2: TX PA2, RX PA3, on APB1. USART3: TX PB10, RX PB11, on APB1. BRR = f_PCLK / baud: USART1 at 72 MHz and 115200 baud gives BRR=0x271; USART2 at 36 MHz and 115200 baud gives BRR=0x138. Enable with USART_CR1 UE, TE, RE. TX pin is AF push-pull (0xB), RX input floating (0x4).

## ADC and timers
ADC1 channels: PA0..PA7 = IN0..IN7, PB0 = IN8, PB1 = IN9; IN16 is the temperature sensor. ADC clock must not exceed 14 MHz: set RCC_CFGR.ADCPRE to /6 for 12 MHz at 72 MHz. Run a calibration (ADC_CR2.CAL) after power-on. PWM: TIM2 CH1-CH4 on PA0-PA3, TIM3 CH1-CH4 on PA6, PA7, PB0, PB1, TIM4 CH1-CH4 on PB6-PB9, TIM1 CH1-CH3 on PA8-PA10 (TIM1 also needs BDTR.MOE=1). Timer clocks are 72 MHz on both buses (APB1 timers are doubled when the APB1 prescaler is not 1).

## Clock tree
HSI is an 8 MHz RC oscillator; the Blue Pill has an 8 MHz HSE crystal. Typical 72 MHz bring-up: enable HSE (RCC_CR.HSEON, wait HSERDY), set FLASH_ACR.LATENCY=2 and PRFTBE, PLLSRC=HSE, PLLMUL=x9, HPRE=/1 (AHB 72 MHz), PPRE1=/2 (APB1 36 MHz, max 36 MHz), PPRE2=/1 (APB2 72 MHz), enable PLL, wait PLLRDY, then SW=PLL and wait SWS=PLL. USB requires exactly 48 MHz via USBPRE=/1.5.

## Toolchain idioms
Bare-metal C uses the CMSIS device header stm32f1xx.h (RCC->APB2ENR, GPIOB->CRL, I2C1->CR1). Build with arm-none-eabi-gcc -mcpu=cortex-m3 -mthumb, the startup file startup_stm32f103xb.s and linker script STM32F103C8Tx_FLASH.ld (64 KB flash at 0x08000000, 20 KB RAM at 0x20000000). Retarget printf by implementing _write() over USART1. SysTick at 72 MHz with LOAD=72000-1 yields a 1 ms tick for delays.

## Known pitfalls
STM32F10x errata: the I2C analog filter can leave the BUSY flag stuck after a glitch; recover by toggling I2C_CR1.SWRST and reconfiguring. I2C1 with remap to PB8/PB9 conflicts with CAN remap. Reading DR before RXNE or clearing ADDR in the wrong order hangs single-byte receptions; follow the reference manual's N=1 and N=2 sequences. Writing CRL/CRH with a plain assignment clobbers the other seven pins of the half-port; use read-modify-write.
